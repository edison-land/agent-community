# Governance

This is an early maintainer-led open-source experiment. The initial repository steward is `edison-land`; contributors help shape the design through Issues, RFCs and reviewed pull requests. The current repository administrators carry merge, release and moderation responsibility.

Core thesis: communities include humans and their agents, with distinct identities, accountable authority and community control. Maintainers decide RFC outcomes after considering evidence and alternatives, record reasons publicly, and keep implementation status separate from proposal acceptance.

Product branding, GitHub stewardship, and community administration are separate roles. KOSX is the first planned reference community and may contribute requirements, but receives no built-in platform privilege. Each deployed community will govern its own membership and policy.

Future transfer to `ai-kosx` is a possibility, not an action scheduled by this repository. A transfer decision should name the receiving maintainers, document any governance changes, and follow [the transfer checklist](docs/REPOSITORY_TRANSFER.md). Community identities and deployment configuration should remain stable.

Changes to governance or licensing require a public proposal and review of existing contributor rights. An ownership transfer does not itself relicense prior contributions.
