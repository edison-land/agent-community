# FlareMo 接入 Demo

目前交付的是 **HTTP 连接器 + 本地模拟服务 + 可视化验收页 + 可选真实实例测试命令**。模拟服务由我们独立编写，只覆盖测试所需接口，没有运行 FlareMo 源码。真实实例尚未验收；A2A、MCP、模型推理和持续同步尚未实现。

## 先看 Demo

使用 Node.js 24，无需安装依赖：

```sh
npm run flaremo:demo
npm run flaremo:ui
```

第二条命令启动后打开 http://127.0.0.1:4318 。点击「运行共享实验」，查看保存、共享、更新、撤回和撤销凭证的实际 HTTP 检查结果。所有数据和凭证都是虚构的，退出后丢弃；页面不能连接真实实例，也不会接收真实令牌。

```sh
npm test
```

测试还包括：错误凭证、禁止重定向、错误响应、请求超时、只读限制和资源路径校验。它们验证我们连接器的行为，不代表 FlareMo 已通过集成验收。

## 六层与协议

详细提案见 [RFC 0003](../RFC/0003-layering-and-flaremo-demo.md)。六层为交互、协作流程、身份与权限、协议与连接器、数据、后台运行。首版可以是一个应用，FlareMo 作为独立知识服务连接。

Agent 之间计划复用 [A2A 官方 JS SDK](https://github.com/a2aproject/a2a-js)，Agent 使用社区工具计划复用 [MCP 官方 TypeScript SDK](https://github.com/modelcontextprotocol/typescript-sdk)。两者仍需版本固定和互通测试；本 Demo 先验证 REST，不自称实现这两个协议。

## 请管理员准备什么

1. 确认实例是 FlareMo，提供测试实例的 HTTPS 根地址和部署版本/提交。不要提供 Cloudflare 后台密码。
2. 在同一测试团队创建两位普通成员 A、B。A 可发布团队笔记；B 是另一位普通成员。不要用实例 owner 代替 B，否则无法验证普通成员权限。
3. 由各测试成员生成短期、可撤销 PAT，通过安全渠道交给测试执行者。令牌权限继承用户，不能假设是仅访问单篇资料的令牌。
4. 明确允许创建/修改虚构资料、在测试团队发布/撤回；软删除单独授权。测试会产生一篇带唯一标记的笔记。确认测试调用处于管理员允许的资源用量范围。
5. 如果实例受 Cloudflare Access 保护，另外提供仅用于该实例的服务访问凭证。该凭证不能替代 A、B 的应用身份。
6. 后续再确认 webhook 的用户订阅范围、签名方式、SSE 访问、限流、附件限制和索引延迟。第一轮不要求修改 FlareMo 源码。

## 真实实例配置

复制 `.env.flaremo.example` 为 `.env.flaremo.local`，只在本机填写。文件被 Git 忽略。不要把真实值放进 Issues、截图、聊天或浏览器页面；输出也不会打印笔记正文或令牌。

默认只读探测：让 A 先手动创建一篇虚构测试笔记，填其 `memos/…` 资源名，再执行：

```sh
node --env-file=.env.flaremo.local apps/flaremo-demo/live.js
```

这一步只说明 A 能读取该资源，不证明跨成员权限。

管理员允许写入与团队共享后执行：

```sh
node --env-file=.env.flaremo.local apps/flaremo-demo/live.js --allow-write
```

它依次检查 A 创建私密笔记、B 被拒绝、A 发布到团队、B 读到原文、A 更新、B 读到新版本、A 撤回私密、B 被拒绝。成功后笔记保留在 A 的私密空间。

只有明确获准把本次测试笔记移入回收站时，才增加 `--allow-trash`：

```sh
node --env-file=.env.flaremo.local apps/flaremo-demo/live.js --allow-write --allow-trash
```

工具只操作本次新建的那一篇笔记；不会硬删除，不会自动重试写入。若超时，服务端可能已经完成写入，按输出的实验标记由 A 人工核对，避免盲目重跑。失败时尽力把已知测试笔记恢复私密，并报告恢复是否成功；无法确认时必须由 A/管理员核查。

真实 B 的凭证撤销需要管理员在 FlareMo 操作，再运行只读探测验证。Demo 不会自动禁用真实账号或撤销真实凭证。

## 验收清单

| 场景 | 应观察到的结果 | 当前证据 |
| --- | --- | --- |
| 私密资料 | B 返回 403 或 404，不能读正文 | 本地 mock；真实待验证 |
| 发布到团队 | B 读到同一份测试正文 | 本地 mock；真实待验证 |
| 更新内容 | B 的下一次读取取得新版本 | 本地 mock；真实待验证 |
| 撤回私密 | B 再次被拒绝；不能使用旧缓存 | 本地 mock；真实待验证 |
| 撤销凭证 | 该凭证被拒绝 | 本地 mock；真实需管理员操作 |
| 软删除 | A 读取到 TRASHED 状态或资源不可用 | 本地 mock；真实须额外授权 |
| 断线、重复/乱序事件 | 恢复最新状态且不重复写入 | 未实现，下一轮同步实验 |
| 真实 A2A Agent 委派 | 任务与成果可归属、可取消、可恢复 | 未实现，后续实验 |

共同保存每轮的部署版本、测试命令、结果和失败步骤。第一轮通过才进入协议 SDK 与持续更新集成；不通过则先定位是权限配置、版本差异还是连接器问题。
