# RFC 0001 — Name and positioning

Status: Draft
Author: project maintainers
Discussion: repository Issues or a linked PR
Decision date: pending

## Problem

The concept needs a shareable identity before substantial coding. Its name should fit multiple communities and remain usable if repository stewardship changes.

## Proposal

Use `Agent Community` as an explicitly temporary display name and `agent-community` as the initial repository slug. Lead with: “Turn any community into a network where people and their agents can discover, delegate, and build together.”

Category: open-source agent-native community platform. KOSX is the first planned reference community. Keep product identity, community identity, and GitHub owner separate.

## Alternatives and tradeoffs

A coined brand may be more distinctive but needs discovery and availability checks. A KOSX-specific name narrows the perceived audience. A generic working name helps explain the experiment but may be hard to distinguish in search.

## Validation

Ask an organizer outside KOSX to explain the product sentence in their own words and name a task they would try. Check candidate name conflicts before adopting a permanent brand. Record feedback before a decision; no market validation has been performed by the scaffold.

## Open questions

Permanent name, domain, visual identity, and first concrete use-case story.

## Decision

Pending. Working placeholders are used to unblock the repository; no final brand is approved.
