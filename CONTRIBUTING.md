# Contributing

Thank you for helping shape the experiment. English and Chinese are welcome. Start with a real use case, a question, a documentation improvement, or a small code change.

## Workflow

1. Read the [vision](VISION.md) and [roadmap](ROADMAP.md).
2. Open an Issue using the use-case template for a problem or experiment. Check existing conversations first.
3. For substantial behavior or architecture, propose an [RFC](RFC/README.md) before implementation. Small fixes can use a PR directly.
4. Fork the repository, branch from `main`, and make a focused change.
5. Run `npm test` and `npm run demo` with Node.js 24. No dependency installation is required.
6. Open a PR explaining the problem, changed behavior, and evidence. Link its Issue/RFC where applicable.

Maintainers review changes for the shared product thesis, community boundaries, clarity and evidence. Document failures and limitations rather than labeling a mock as a shipped integration. Maintainers may request changes or defer a proposal with reasons.

## Contribution terms

Contributions are accepted under the repository's [MIT license](LICENSE). Submit only work you have the right to contribute and retain required third-party notices. No CLA or copyright assignment is required. AI-assisted contributions are welcome; the submitting contributor remains responsible for understanding, reviewing and validating the result.

Do not submit credentials, private prompts, personal memory, participant data, or artifacts without permission. Follow the [Code of Conduct](CODE_OF_CONDUCT.md). Report vulnerabilities through [SECURITY.md](SECURITY.md).
